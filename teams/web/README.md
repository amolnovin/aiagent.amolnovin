## چطور در همین چت استفاده کنی

فقط پروژه‌ات را بنویس. مثال:

> «یک سایت شرکتی برای کلینیک دندانپزشکی می‌خوام؛ ۵ صفحه، فرم نوبت‌دهی و پنل ادمین.»

تیم این‌طور جواب می‌دهد:

```
UX  → نقشه سایت + جریان کاربر + وایرفریم متنی
UI  → توکن‌های رنگ/فونت + طراحی هر کامپوننت
FE  → کد HTML/CSS/JS
BE  → کد PHP، ساختار دیتابیس، API، امنیت
QA  → چک‌لیست تست + گزارش ممیزی + دستورات دیپلوی
```

### دستورات سریع (در چت بنویس)

| دستور | نتیجه |
|-------|-------|
| `/all <توضیح>` | هر ۵ ایجنت به‌ترتیب روی موضوع کار می‌کنند |
| `/ux <سؤال>` | فقط دیدگاه معمار تجربه |
| `/ui <سؤال>` | فقط دیدگاه طراح بصری |
| `/fe <سؤال>` | فقط دیدگاه مهندس فرانت‌اند |
| `/be <سؤال>` | فقط دیدگاه مهندس PHP |
| `/qa <سؤال>` | فقط دیدگاه مدیر کیفیت |
| `/review <کد یا لینک>` | کد ریویوی کامل تیم (۵ دیدگاه) |
| `/ship` | بسته‌ی نهایی آماده‌ی دیپلوی + چک‌لیست راه‌اندازی |

## قابلیت‌های on-demand (با جمله‌ی کلیدی)

این چهار مورد ایجنت جدید نیستند — همان ۵ عضو، با چک‌لیست اجباری. چون داخل فایل‌ها نوشته شده‌اند، در Claude/Cursor و پروژه‌های بعدی هم کار می‌کنند.

| جمله‌ی کلیدی | مجری | محل چک‌لیست |
|---|---|---|
| «سئو و محتوایش را هم بنویس» | رهبر + `UX` + `FE` | `UX` §هـ استراتژی محتوا و سئو / `FE` §SEO تکنیکال |

| «راهنمای دیپلوی بده» | `BE` + `QA` | `BE` §Deploy & Ops / `QA` §چک‌لیست راه‌اندازی + §تحویل: مستند فنی |

## قانون‌های ثابت تیم

1. **هیچ کدی بدون قرارداد UX/UI نوشته نمی‌شود** — اول جریان و طراحی، بعد کد.
2. **هر تحویل باید قابل اجرا باشد** — کد کامل، نه شبه‌کد؛ با توضیح «کجا بگذارمش».
3. **RTL اول** — چیدمان از روز اول دوزبانه و راست‌به‌چپ طراحی می‌شود (`dir="rtl"`، منطق منطقی CSS مثل `margin-inline-start`).
4. **دسترس‌پذیری اجباری** — هدف WCAG 2.2 AA؛ کنتراست، کیبورد، `aria`، تمرکز.
5. **امنیت پیش‌فرض** — prepared statements، اعتبارسنجی سمت سرور، CSRF، هدرهای امنیتی.
6. **هر خروجی با «چک‌لیست تأیید» بسته می‌شود** تا بدانی چه چیزی تست شده و چه چیزی نه.
