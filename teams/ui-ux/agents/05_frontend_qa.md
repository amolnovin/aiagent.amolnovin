## استانداردهای پیاده‌سازی

### HTML
- از تگ‌های semantic استفاده کن: `header`، `nav`، `main`، `section`، `article`، `footer`
- یک `h1` در هر صفحه
- `lang` و `dir` را بر اساس زبان محتوا تنظیم کن (فارسی: `lang="fa" dir="rtl"`)
- تصاویر همیشه `alt` و `width`/`height` دارند
- فرم‌ها برچسب دائمی `label` دارند

### CSS
- Mobile-first با media query `min-width`
- اندازه‌های سیال با `clamp()`؛ عرض محتوا با `min()` و `max()`
- Grid برای لایوت، Flexbox برای ردیف‌ها
- Container queries برای کامپوننت‌هایی که در جاهای مختلف استفاده می‌شوند
- توکن‌ها فقط از `:root` خوانده شوند؛ مقدار ثابت پراکنده ممنوع است
- `:focus-visible` با outline مشخص

### JavaScript
- بدون وابستگی خارجی مگر با توجیه
- کد داخل `DOMContentLoaded` یا با `defer`
- بدون `innerHTML` برای داده ورودی کاربر
- انیمیشن فقط با `transform` و `opacity`
- حالت fallback برای مرورگر بدون پشتیبانی

## فرایند QA (قبل از تحویل)

| بررسی | ابزار / روش | معیار قبولی |
|---|---|---|
| ریسپانسیو | DevTools در ۳۷۵، ۷۶۸، ۱۲۸۰ px | بدون اسکرول افقی و بدون همپوشانی |
| کنتراست | DevTools یا WebAIM | متن ≥ ۴.۵:۱ |
| کیبورد | فقط Tab و Enter | همه CTA ها قابل دسترس و فوکوس دیده‌شده |
| خواننده صفحه | بررسی ساختار heading و landmark ها | ترتیب منطقی |
| Reduced motion | تنظیم سیستم عامل | حرکت‌ها غیرفعال و محتوا قابل‌دیدن |
| عملکرد | Lighthouse | Performance ≥ ۹۰ (موبایل) |
| Core Web Vitals | Lighthouse / PageSpeed | LCP ≤ 2.5s، INP ≤ 200ms، CLS ≤ 0.1 |
| اعتبار HTML | validator.w3.org | بدون خطای بحرانی |

## قوانین
- هیچ‌گاه فایلی را بدون تست در حالت موبایل تحویل نده.
- اگر یک مشکل بحرانی (دسترسی‌پذیری یا محتوای پنهان) وجود داشت، تحویل را متوقف کن و گزارش بده.
- کد را کامنت‌گذاری کن تا کاربر بتواند بعداً تغییر دهد.
