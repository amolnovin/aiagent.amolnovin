# استاندارد بذرگذاری محتوای واقعی (Content Seeding)

> **مشکلی که این استاندارد می‌بندد:** قالب با «داده‌ی نمایشی» تحویل می‌شود و بعد از نصب، سایت خالی/شبیه
> دمو است یا متن‌ها فقط یک لایه‌ی HTML ثابت‌اند. اینجا برعکس است: **از HTML منبع، داده ساخته می‌شود**
> (برگه‌ها، نوشته‌ها، محصولات، منوها) تا قالب با داده‌ی واقعی زنده شود — مثل کار یک توسعه‌دهنده‌ی انسانی.
> **مالک اجرا:** `WP` · **استخراج محتوا:** `CONV` · تصاویر: `MEDIA` · **دروازه:** `QA`
> مکمل: `woocommerce-integration.md` (محصولات و صفحات WC) · `conversion-checklist.md` §2 (داده‌ی زنده)

---

## ۱) قانون اصلی

> **قالب بدون محتوا = نیمه‌تمام.** هر تحویل قالب، همراه با **Seeder** است که با یک کلیک، سایت را با
> محتوای واقعیِ همان HTML پر می‌کند. کارفرما بعد از نصب نباید با سایت خالی یا محصولات فرضی روبه‌رو شود.

---

## ۲) ورودی: فهرست محتوای استخراج‌شده (CONTENT MANIFEST)

`CONV` حین مرحلهٔ CONVERT، محتوای هر بلوک را از HTML منبع استخراج و در `docs/content-manifest.md` می‌ریزد —
این فایل **ورودی مستقیم Seeder** است:

```markdown
## content-manifest.md (نمونه)
| بلوک | نوع داده | مقدار از HTML | مقصد در وردپرس |
|---|---|---|---|
| hero | متن + تصویر + CTA | «بهترین چادر مسافرتی…» + hero.jpg | تنظیمات قالب (تب صفحات) + رسانه |
| محصولات ویترین | ۶ کارت محصول | نام/قیمت/تصویر نمونه | ۶ WC product + دسته‌ها |
| مقالات اخیر | ۳ کارت | عنوان/خلاصه/تصویر | ۳ WP post (دستهٔ حوزه) |
| نمونه‌کارها | ۴ آیتم | عنوان + لینک + تصویر | CPT + ۴ رکورد |
| تماس | تلفن/ایمیل/آدرس/نقشه | از HTML | تنظیمات قالب (تب تماس) |
| منو | ساختار لینک‌ها | nav سراسری HTML | menu اصلی + فوتر |
```

**قواعد استخراج:**
- متن واقعی HTML کپی می‌شود (نه lorem، نه «محصول ۱») — اما قیمت/تلفن نمونه اگر محرمانه است، معادل واقع‌گرایانه جایگزین می‌شود و در manifest یادداشت می‌شود.
- تعداد آیتم‌های هر لوپ از HTML خوانده می‌شود (مثلاً ۶ محصول، ۳ مقاله).
- هر تصویر به `MEDIA` تحویل داده می‌شود تا با بودجه بهینه داخل `assets/images/demo/` قرار گیرد.

## ۳) خروجی: Seeder اجباری (یکی از دو روش)

### روش الف (ترجیحی): بذر برنامه‌نویسی‌شده — `inc/seed/`
```
inc/seed/
├── Seeder.php          ← هسته: run() با capability + nonce + حالت ایدمپوتنت
├── pages.php           ← برگه‌ها (خانه با همهٔ بخش‌ها، درباره، تماس، خدمات/فروشگاه)
├── posts.php           ← ۳–۵ نوشته با متن واقعی حوزه + دسته/برچسب + تصویر شاخص
├── products.php        ← حوزهٔ فروشگاهی: ۸–۱۲ محصول (قیمت، موجودی، دسته، گالری، توضیح)
├── taxonomy.php        ← دسته‌ها/برچسب‌ها/منوها (اصلی + فوتر)
├── settings.php        ← صفحهٔ خانه، صفحات WC، خواندن، لینک ثابت در صورت نیاز
└── cpts.php            ← رکوردهای CPTهای حوزه (خدمات، نمونه‌کار، …)
```

### روش ب: فایل WXR — `content/seed.xml`
- استاندارد WordPress eXtended RSS با همه‌ی برگه‌ها/نوشته‌ها/محصولات/منوها + پیوست تصاویر.
- دکمهٔ «درون‌ریزی محتوا» با `WP_Widget_Importer`/`wordpress-importer` داخلی (بدون افزونهٔ جانبی اجباری).

### اتصال به پنل
دکمهٔ **«راه‌اندازی و محتوای نمونه»** در پنل تنظیمات (تب «صفحات» یا بخش جداگانه):
- فقط `manage_options` + `wp_nonce_field`
- **ایدمپوتنت:** اگر برگه/محصول با همان عنوان/slug وجود دارد، ساخته نمی‌شود؛ اجبار دوباره = «همه‌چیز موجود بود»
- پیام فارسی موفقیت + تعداد ساخته‌شده‌ها + **پاک‌سازی کش** بعد از اجرا (مطابق `theme-settings-standard.md` §8)
- دکمهٔ «پاک‌سازی محتوای نمونه» فقط برای محیط توسعه و با confirm صریح (هرگز پیش‌فرض نیست)

## ۴) حداقل محتوای هر تحویل

| آیتم | حداقل |
|---|---|
| برگهٔ خانه | همهٔ بخش‌های HTML منبع، با داده‌ی واقعی هر بلوک |
| برگه‌های ثابت | درباره + تماس + (خدمات یا فروشگاه طبق حوزه) — با متن واقعی HTML |
| نوشته‌ها | ۳–۵ مقاله با عنوان/خلاصه/متن واقع‌گرایانه حوزه + تصویر شاخص |
| محصولات (حوزهٔ فروشگاهی) | ۸–۱۲ محصول: قیمت، موجودی، ۲+ تصویر، توضیح، دسته + ۳ دسته |
| CPTهای حوزه | ≥۳ رکورد برای هر CPT (خدمات/نمونه‌کار/…) |
| منوها | منوی اصلی + فوتر با لینک‌های همان HTML |
| تنظیمات وردپرس | صفحهٔ خانه انتخاب‌شده، صفحات ووکامرس (Shop/Cart/Checkout/Account) انتخاب‌شده |
| تصاویر | از `assets/images/demo/` با بودجهٔ `MEDIA` (hero ≤۱۰۰KB، thumb ≤۳۰KB) — منبع/مجوز ثبت‌شده |

## ۵) قواعد کیفیت

1. **زنده، نه نمایشی:** متن‌ها باید از دل HTML منبع بیایند؛ بعد از نصب، **همان چیزی دیده می‌شود که در HTML دیده بود**.
2. **بعد از بذرگذاری، داده از ادمین قابل ویرایش است** (باغبان سایت می‌تواند قیمت/متن را عوض کند) — هیچ‌چیز به view هاردکد نمی‌شود.
3. **بدون اختراع محتوا:** چیزی خارج از HTML منبع/بریف ساخته نمی‌شود؛ اگر HTML چیزی نداشت، manifest خالی می‌ماند و `TL` تصمیم می‌گیرد.
4. **همه‌ی CPTها با ABSPATH guard و بدون fatal** (مرجع: `fatal-error-prevention.md`).
5. **i18n:** متن‌های بذرخورده هم در صورت نیاز با text domain قالب.

## ۶) چک‌لیست پذیرش (توسط `QA`)

- [ ] `docs/content-manifest.md` کامل است (هر بلوک HTML یک ردیف)
- [ ] Seeder وجود دارد (`inc/seed/` یا `content/seed.xml`) و از پنل با یک کلیک اجرا می‌شود
- [ ] نصب تمیز → فعال‌سازی قالب → اجرای Seeder → **سایت پر است و شبیه HTML منبع**
- [ ] اجرای دوباره، چیزی را تکرار/خراب نکرد (ایدمپوتنت)
- [ ] برگهٔ خانه همهٔ بخش‌ها را با داده‌ی واقعی دارد؛ خبری از متن استاتیک در viewها نیست
- [ ] حوزهٔ فروشگاهی: ≥۸ محصول واقعی + صفحات WC انتخاب‌شده + تست‌های `woocommerce-integration.md` §5
- [ ] تغییر هر مقدار در ادمین، بلافاصله در front دیده می‌شود (تست زنده بودن)
- [ ] `python3 scripts/validate_theme.py` سبز
