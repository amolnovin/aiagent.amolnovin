# استاندارد یکپارچه‌سازی ووکامرس ( WooCommerce Integration )

> **مشکلی که این استاندارد می‌بندد:** قالب حوزه‌ی فروشگاهی با داده‌ی نمایشی ساخته می‌شود، اما به‌محض افزودن
> محصول واقعی، صفحات **تک‌محصول، سبد خرید، تسویه حساب و … با قالب پیش‌فرض ووکامرس** نمایش داده می‌شوند.
> **مالک اجرا:** `WP` · پشتیبان: `CONV` (بلوک‌های HTML) · **دروازه:** `QA` + `scripts/validate_theme.py`
> پیش‌نیازها: `theme-settings-standard.md` (تب «کنترل فروشگاه») · `fatal-error-prevention.md` (گارد بدون-Woo)

---

## ۱) قانون اصلی

**هر صفحه‌ای که در HTML منبع هست و ووکامرس آن را می‌سازد، باید توسط قالب override شود.**
قالب پیش‌فرض ووکامرس فقط برای صفحه‌ای قابل قبول است که اصلاً در HTML منبع طراحی نشده باشد — و آن را هم
باید در گزارش `QA` ثبت کنیم.

```
HTML منبع: صفحهٔ محصول، سبد خرید، تسویه حساب دارد
     ↓
قالب موظف است: woocommerce/ در ریشهٔ قالب با override همان فایل‌ها
     ↓
نتیجه: دادهٔ واقعی ووکامرس (قیمت، موجودی، سفارش) داخل طراحی HTML
```

---

## ۲) الزامات فنی

### الف) اعلان پشتیبانی + گاردها
```php
// در provider مربوطه (نه functions.php):
add_theme_support('woocommerce', [
    'gallery_thumbnail_image_size' => 'woocommerce_gallery_thumbnail',
    'gallery_zoom' => true,
    'gallery_lightbox' => true,
    'gallery_slider' => true,
]);
add_theme_support('wc-product-gallery-zoom');
add_theme_support('wc-product-gallery-lightbox');
add_theme_support('wc-product-gallery-slider');
```
- **بدون ووکامرس = بدون fatal:** هر کد وابسته به Woo پشت `class_exists('WooCommerce')` باشد
  (الگوی `fatal-error-prevention.md` §3).
- فایل‌های override داخل `{theme}/woocommerce/` فقط وقتی Woo فعال است load می‌شوند؛ اما خود فایل‌ها
  هم `defined('ABSPATH') || exit` دارند و هیچ کلاس Woo را در لودِ فایل صدا نمی‌زنند.

### ب) مسیر override = همان مسیر داخل `woocommerce/templates/` ووکامرس
```
{theme}/woocommerce/
├── archive-product.php          ← فروشگاه/آرشیو (گرید محصولات)
├── content-product.php          ← کارت محصول در گرید (یا loop/content-product.php — طبق نسخهٔ Woo)
├── single-product.php           ← قاب تک‌محصول
├── content-single-product.php   ← بدنهٔ تک‌محصول: گالری، قیمت، افزودن به سبد، توضیحات
├── cart/
│   ├── cart.php                 ← جدول سبد، کد تخفیف، خلاصه
│   ├── mini-cart.php            ← سبد کوچک هدر
│   └── proceed-to-checkout-button.php
├── checkout/
│   ├── form-checkout.php        ← چیدمان فرم تسویه
│   ├── form-billing.php         ← بخش‌های فرم (در صورت طراحی متفاوت)
│   └── thankyou.php             ← صفحهٔ سفارش موفق
└── (در صورت وجود در HTML: global/، loop/، single-product/product-*.php)
```
> **قانون طلایی:** لیست دقیق فایل‌ها را از **نسخهٔ ووکامرس نصب‌شده** استخراج کن — `grep -r "wc_get_template"`
> روی کد WC یا مقایسه با `woocommerce/templates/` همان نسخه. فهرست بالا حداقل است، نه سقف.
> فایل‌هایی که طراحی‌شان را HTML منبع عوض نمی‌کند، override نکن (کم‌نگه‌دار تا بروزرسانی WC ساده باشد).

### ج) حتماً `add_theme_support('woocommerce')` ثبت شود
بدون آن، ووکامرس با قالب‌های ساده‌تر/پیش‌فرض خودش رندر می‌شود حتی اگر فایل override موجود باشد (در بعضی مسیرها). اگر `woocommerce/` در قالب هست ولی support ثبت نشده = **FAIL**.

## ۳) قواعد رندر با داده‌ی واقعی

1. **قیمت:** همیشه از `wc_price()` / اسکیمای `price` ووکامرس — عدد دستی ممنوع.
2. **موجودی/ناموجودی:** `wc_get_stock_html()` — رنگ و برچسب از HTML منبع.
3. **افزودن به سبد:** `woocommerce_template_loop_add_to_cart` / `wc_get_template('single-product/add-to-cart')` با همان کلاس‌های دکمهٔ HTML.
4. **گالری تک‌محصول:** از داده‌ی واقعی محصول (`woocommerce_product_gallery`) با کلاس‌های HTML منبع.
5. **mini-cart هدر:** تعداد و مبلغ از `WC()->cart` — بعد از `added_to_cart` بدون reload.
6. **فیلترهای Woo:** از هوک‌ها استفاده کن (`woocommerce_before_shop_loop_item_title` و…) تا بروزرسانی WC چیزی را نشکند؛ فقط وقتی هوک جا نمی‌دهد، فایل را override کن.
7. **بدون داده‌ی نمایشی hardcode:** هیچ محصول/قیمت/موجودی ثابتی در view نیست (قانون داده‌ی زنده: `conversion-checklist.md` §2).

---

## ۴) تب «کنترل فروشگاه» پنل تنظیمات

طبق `theme-settings-standard.md`: تعداد محصول/ستون، ویترین خانه، نمایش تخفیف‌ها، وضعیت ووکامرس — همه از
schema خوانده می‌شوند. صفحات ووکامرس (فروشگاه، سبد، تسویه، حساب) بعد از **بذرگذاری** (`content-seeding.md`)
در «تنظیمات ← عمومی» وردپرس انتخاب می‌شوند — این کار را Seeder خودکار انجام می‌دهد، نه کاربر.

## ۵) پروتکل تست با داده‌ی واقعی (اجباری — مال `QA`)

> «قالب پیش‌فرض WC دیدم» = یکی از این تست‌ها FAIL است.

| # | تست | مراحل | معیار PASS |
|---|---|---|---|
| T1 | فعال‌سازی تمیز | نصب وردپرس خام + قالب + ووکامرس | صفر fatal، صفر notice (`WP_DEBUG`) |
| T2 | بذرگذاری | یک کلیک «راه‌اندازی محتوا» | ≥۸ محصول با تصویر/قیمت/دسته، برگه‌ها، منوها ساخته شد؛ اجبار دوباره چیزی را تکرار نکرد |
| T3 | فروشگاه | `/shop/` یا آرشیو دسته | گرید و کارت محصول **طراحی HTML** است، نه WC پیش‌فرض |
| T4 | تک‌محصول | باز کردن یک محصول واقعی | گالری/قیمت/افزودن به سبد/توضیحات/مرتبط‌ها با طراحی HTML |
| T5 | سبد | افزودن ۲ محصول → mini-cart → صفحه سبد | mini-cart هدر به سبک HTML؛ جدول سبد override شده |
| T6 | تسویه | فرم تسویه + پرداخت تست | فرم‌ها با طراحی HTML؛ سفارش ثبت شد |
| T7 | سفارش موفق | باز کردن صفحهٔ سفارش | `thankyou.php` override شده |
| T8 | حالت خالی | سبد خالی، جست‌جوی بدون نتیجه | پیام فارسی به سبک HTML (نه متن پیش‌فرض انگلیسی WC) |
| T9 | بدون ووکامرس | غیرفعال کردن WC → رفرش | بدون fatal؛ سایت بقیه‌جاها کار می‌کند |
| T10 | تغییر داده در ادمین | تغییر قیمت/موجودی یک محصول → رفرش | همان‌جا در front تغییر کرد (اثبات زنده بودن) |

نتیجه در `docs/05-qa-report.md` با شاهد (اسکرین‌شات هر صفحه) ثبت می‌شود.
