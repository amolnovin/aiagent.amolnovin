# پروتکل همکاری تیم — HTML به قالب وردپرس Sage (بدون Composer)

این فایل قانون کار گروهی **۱۴ ایجنت** این تیم است. هر پروژه‌ی تبدیل HTML به قالب وردپرس، این جریان را اجرا می‌کند.

---

## ۱) جریان کار (Pipeline)

```
 ۰. INTAKE        TL        : بریف، تعریف حوزه کاری، محدودیت‌ها، بودجه عملکرد
 ۱. AUDIT         ARCH      : ممیزی HTML منبع، فهرست دارایی‌ها، تصمیم ثالث‌ها
 ۲. BENCHMARK     BENCH     : آنالیز رقبای فارسی و غیرفارسی، الگوهای برتر، شکاف‌های سئو
 ۳. STRUCTURE     ARCH + SAGE : قرارداد تبدیل + اسکلت بدون-Composer (autoloader، مینی-Blade، config، routes)
 ۴. CONVERT       CONV      : HTML → Blade (layout، partials، components، لوپ‌ها)
 ۵. STYLE         CSS       : توکن‌ها، ریسپانسیو ۳۶۰/۷۶۸/۱۴۴۰، RTL، WCAG
 ۶. MEDIA         MEDIA     : پک آیکون، تصاویر مرتبط، بهینه‌سازی، media library، دارایی‌های برند
 ۷. ASSETS        JS        : کامپوننت‌های تعاملی، Vite (npm)، حالت no-build
 ۸. UI-REVIEW     UXR       : بازبینی مستقل UI/UX + نقشه‌ی راه‌حل‌های اولویت‌بندی‌شده (P0/P1/P2)
 ۹. INTEGRATE     WP        : هوک‌ها، enqueue، theme.json، Settings API، امنیت، i18n
۱۰. EXTEND        PLUG      : افزونه‌های داخلی پروژه (فرم‌ها، CPTها، ماژول‌های حوزه)
۱۱. OPTIMIZE-SEO  SEO       : متاتگ‌ها، Schema حوزه، سلسله‌مراتب عنوان، سئوی فارسی
۱۲. OPTIMIZE-PERF PERF      : بودجه عملکرد، تصویر/فونت/JS/CSS، اثبات ≥ ۹۰
۱۳. VERIFY        QA        : تست، خطایابی، رگرسیون با منبع، دروازه‌ی انتشار
۱۴. SHIP          TL + QA   : بسته‌ی نهایی + docs + استاندارد قابل‌استفاده‌ی مجدد حوزه
```

**قاعده:** مرحله ۲ (BENCHMARK) موازی با مرحله ۱ اجرا می‌شود و خروجی‌اش ورودی مراحل ۳، ۸ و ۱۱ است. مراحل ۴ تا ۷ می‌توانند تا حدی موازی بروند، به‌شرطی که **قرارداد تبدیل (Conversion Contract)** در مرحله ۳ امضا شده باشد و `MEDIA` قبل از تحویل به `UXR` مانیفست تصاویر را بسته باشد. هیچ مرحله‌ای از ۹ به بعد شروع نمی‌شود مگر اقدامات **P0 مرحله ۸ (UI-REVIEW)** بسته شده باشد. مرحله ۱۳ فقط با PASS می‌بندد.

---

## ۲) قرارداد تبدیل (Conversion Contract) — پل بین معماری و کد

قبل از نوشتن کد، `ARCH` این جدول را می‌بندد و بقیه بر اساس آن کار می‌کنند:

```
SOURCE BLOCK            → TARGET FILE                          → DYNAMIC DATA
──────────────────────────────────────────────────────────────────────────────
<header class="navbar"> → resources/views/layout/app.blade.php  → wp_nav_menu
<section id="hero">     → partials/blocks/hero.blade.php        → theme mod: hero_title
<form id="contact">     → partials/forms/contact.blade.php     → nonce + admin-ajax
<div class="svc-card">  → components/service-card.blade.php    → WP loop / CPT
<footer class="footer"> → layout/footer.blade.php               → widgets + social mods
```

**قاعده:** هیچ بلوکی خارج از قرارداد ساخته نمی‌شود؛ تغییر قرارداد = تصمیم ثبت‌شده‌ی `TL` + اطلاع به همه.

---

## ۳) قالب تحویل بین ایجنت‌ها (Handoff)

هر ایجنت خروجی‌اش را با این سربرگ می‌دهد:

```
👤 [کد] نام ایجنت — مرحله N
─────────────────────────────
📌 خروجی: چه چیزی ساخته شد
📥 ورودی گرفته‌شده از: کدام ایجنت / کدام تصمیم
⚠️ ریسک‌ها و فرض‌ها: چه چیزی حدس زده شد و باید تأیید شود
➡️ تحویل به: چه کسی، برای چه کاری
```

---

## ۴) جدول مسیریابی (چه کاری به چه کسی)

| درخواست کاربر | مسئول اصلی | پشتیبان |
|---|---|---|
| «این HTML را تبدیل کن» / بریف پروژه | TL | ARCH |
| ممیزی HTML، نقشه‌ی فایل‌ها، قرارداد تبدیل | ARCH | TL |
| «رقبا را بررسی کن» / آنالیز سایت فارسی و خارجی حوزه | BENCH | SEO + UXR |
| ساختار پوشه‌ها، autoloader، موتور قالب | SAGE | ARCH |
| تبدیل بخش‌ها به Blade، لوپ‌ها، فرم‌ها | CONV | SAGE + WP |
| رنگ، فونت، چیدمان، ریسپانسیو، RTL | CSS | CONV |
| پک آیکون، تصاویر، بهینه‌سازی، media library | MEDIA | CSS + UXR |
| منوی موبایل، آکاردئون، فرم AJAX، build | JS | WP |
| بازبینی UI/UX، مشکلات تبدیل و تعامل، راه‌حل | UXR | BENCH + CSS |
| هوک‌ها، enqueue، theme.json، امنیت، i18n | WP | SAGE + JS |
| افزونه‌ی داخلی: فرم، CPT، ماژول حوزه | PLUG | WP + CONV |
| متاتگ، Schema، سلسله‌مراتب عنوان، سئوی فارسی | SEO | WP + BENCH |
| سرعت، Core Web Vitals، تصویر/فونت، کش | PERF | CSS + JS + WP |
| تست، باگ، خطایابی، رگرسیون، دروازه انتشار | QA | همه |
| سرعت ≥ ۹۰ و سئوی حرفه‌ای (هر لحظه) | PERF + SEO | TL |
| تحویل نهایی، مستندات، استاندارد حوزه | TL | QA |

## ۵) تعریف «تمام‌شده» (Definition of Done)

یک مرحله وقتی تمام است که **همه‌ی** این‌ها درست باشند:

**TL**
- [ ] بریف و حوزه‌ی کاری تأیید و Decision Log به‌روز است
- [ ] هر تحویل سربرگ Handoff دارد و چک‌لیست مرحله پر شده

**ARCH**
- [ ] هر بلوک HTML منبع در قرارداد جا دارد (بدون جاافتادگی)
- [ ] ساختار فایل‌ها با `standards/sage11-structure.md` یکی است

**BENCH**
- [ ] ۵ تا ۱۰ رقیب فارسی **و** غیرفارسی با لینک و تاریخ بازدید ثبت شده
- [ ] ماتریس بنچمارک کامل است و هر درس، مسئول و اقدام دارد
- [ ] شکاف‌های سئو به `SEO` و الگوهای برتر به `ARCH`/`UXR` تحویل داده شده

**SAGE**
- [ ] بدون Composer و بدون vendor بالا می‌آید؛ `WP_DEBUG` صفر notice
- [ ] `{{ }}` خروجی‌ها را escape می‌کند؛ `functions.php` فقط bootstrap است

**CONV**
- [ ] جدول تبدیل ۱:۱ با قرارداد؛ هیچ متن/لینک استاتیکِ قابل‌ویرایش نمانده
- [ ] یک `H1` در هر الگو؛ markup معنایی و فرم‌ها nonce‌دار

**CSS**
- [ ] بدون hex پراکنده؛ ۳۶۰/۷۶۸/۱۴۴۰ بدون اسکرول افقی؛ RTL با logical properties
- [ ] کنتراست ≥ 4.5:1؛ focus-visible و reduced-motion

**JS**
- [ ] بدون jQuery؛ همه‌ی اسکریپت‌ها defer/module؛ صفر خطای کنسول
- [ ] build با npm (بدون Composer) + حالت no-build کارا

**WP**
- [ ] صفر notice با `WP_DEBUG`؛ escape سه‌لایه؛ nonce + بررسی سمت سرور
- [ ] منو، لوگو، ویجت، image sizes، textdomain ثبت شده

**MEDIA**
- [ ] پک آیکون یکدست است (گرید ۲۴، stroke، currentColor، sprite + RTL-safe)
- [ ] هر تصویر اسلات دارد، alt واقعی، width/height و داخل بودجه (hero ≤ ۱۰۰KB، thumb ≤ ۳۰KB)
- [ ] مانیفست تصاویر + منبع/مجوز هر فایل ثبت شده و به `SEO`/`PERF` تحویل داده شده

**UXR**
- [ ] ارزیابی هیوریستیک ۱۰ اصلی با نمره و شاهد انجام شده
- [ ] هر مشکل P0/P1 راه‌حل مشخص و مسئول دارد و P0ها قبل از مرحله ۹ بسته شده
- [ ] نسخه‌ی قبلی بازبینی (در صورت وجود) re-test شده

**PLUG**
- [ ] هر افزونه با ABSPATH guard، nonce، sanitize/escape و uninstall تمیز
- [ ] محتوای کارفرما با عوض شدن قالب حفظ می‌شود (CPT در افزونه)
- [ ] API عمومی افزونه برای `CONV` مستند شده

**SEO**
- [ ] title/canonical درست؛ یک H1؛ alt واقعی؛ Schema حوزه بدون تداخل افزونه
- [ ] توضیح متا ۱۲۰–۱۵۵ نویسه، نیم‌فاصله‌های فارسی درست

**PERF**
- [ ] Lighthouse موبایل **و** دسکتاپ ≥ ۹۰ با شاهد مکتوب
- [ ] LCP ≤ 2.5s | INP ≤ 200ms | CLS ≤ 0.1 | فونت فارسی subset

**QA**
- [ ] ماتریس تست کامل (ریسپانسیو، RTL/LTR، کیبورد، فرم‌ها، امنیت)
- [ ] رگرسیون بلوک‌به‌بلوک با HTML منبع؛ گزارش با PASS/FAIL

## ۶) قوانین حل اختلاف

1. اختلاف ساختاری (فایل/قرارداد) → **قرارداد تبدیل `ARCH`** رأی نهایی است.
2. اختلاف ظاهری (CSS در برابر وفاداری به منبع) → **منبع HTML + برند** رأی نهایی است.
3. اختلاف سرعت در برابر ظاهر/سئو → **Performance ≥ ۹۰** خط قرمز است؛ راه‌حل جایگزین پیدا می‌شود، عدد پایین نمی‌آید.
4. اختلاف سئو در برابر تداخل افزونه → **افزونه‌ی سئو منبع حقیقت متاها** است؛ قالب fallback تمیز دارد.
5. در همه‌ی موارد، `TL` با ذکر دلیل در Decision Log تصمیم می‌گیرد.

## ۷) خروجی استاندارد هر پروژه

```
release/
├── theme-name/                  ← قالب نهایی (ساختار sage11-structure.md)
├── plugins/                     ← افزونه‌های داخلی پروژه (PLUG)
│   └── theme-name-<module>/     # فرم، CPT، ماژول حوزه — مستقل از قالب
└── docs/
    ├── 00-benchmark-report.md   # آنالیز رقبای فارسی و غیرفارسی (BENCH)
    ├── 01-brief.md              # بریف تأییدشده + Decision Log
    ├── 02-conversion-report.md  # جدول تبدیل HTML → WP
    ├── 03-seo-report.md         # متاتگ‌ها، Schema، چک‌لیست سئو
    ├── 04-performance-report.md # اثبات Lighthouse ≥ ۹۰ (قبل/بعد)
    ├── 05-qa-report.md          # ماتریس تست، باگ‌ها، PASS/FAIL
    ├── 06-domain-standard.md    # استاندارد قابل استفاده‌ی مجدد این حوزه
    ├── 07-ui-ux-review.md       # بازبینی UI/UX و نقشه‌ی بهبودها (UXR)
    └── 08-media-report.md       # مانیفست آیکون‌ها و تصاویر + بودجه (MEDIA)
```

**نکته‌ی حوزه‌ای:** هر پروژه علاوه بر قالب، یک `06-domain-standard.md` تولید می‌کند تا نوبت بعدی همان حوزه (مثلاً «پزشکی») بدون شروع از صفر، با همان الگوها، بودجه و Schema ساخته شود.
